# Конфигурация маршрутов ИИ

Какие модели Yandex есть в системе, какой процесс какую модель использует, какие сервисы и функции включены — это **документ конфигурации**. Он хранится в БД версиями. Админ платформы меняет его в «Настройки → Модели → Маршруты ИИ». Изменение действует на всех серверах за ≤ 30 секунд, без деплоя и перезапуска.

Секреты в документе не хранятся: ключи и каталог Yandex — только в env (Secret `crm-env`). Провайдер в документе не задаётся: единственное подключение — Yandex AI Studio, оно задано в коде.

Решения и история: [docs/ai/config-in-db-spec.md](../ai/config-in-db-spec.md).

## Документ (схема версии 2)

```jsonc
{
  "version": 2,
  "features": {                       // функции
    "webSearch": true,                // веб-поиск в чате
    "websiteFetch": false,            // чтение сайтов компаний
    "browserSpeechRecognition": false,// голосовой ввод средствами браузера
    "serverSpeechRecognition": true   // голосовой ввод через SpeechKit
  },
  "files": { "images": "vision", "maxMediaSeconds": 180, "pdfMaxPages": 10 },
  "services": { "ocr": true, "speech": true, "search": true },
  "models": {
    "yandex-text":   { "enabled": true, "label": "Yandex AI Studio", "uri": "gpt://<каталог>/…",
                       "capabilities": ["text", "structuredOutput", "tools", "streaming"] },
    "yandex-vision": { "enabled": true, "label": "Yandex Vision", "uri": "gpt://<каталог>/…",
                       "capabilities": ["text", "image"] }
  },
  "tasks": {
    "chat": { "enabled": true, "defaultModel": "yandex-text", "allowedModels": ["yandex-text"] }
    // … остальные процессы, см. ai-overview.md
  }
}
```

Проверки документа ([config.ts](../../src/server/ai/config.ts), строгая схема):

- Неизвестные поля запрещены (в том числе старые `policy`, `connections`, `preprocessing`, `fallbackModels`).
- У включённой модели обязателен `uri` формата `gpt://<каталог>/<модель>`.
- Модель процесса по умолчанию должна быть в его списке разрешённых и включена.
- `parsePdf` требует `services.ocr`; `parseAudio` и голосовой ввод через SpeechKit — `services.speech`; `webSearch` и `companyResearch` — `services.search`; `parseImage` при `images = vision` — включённый `describeImage`.
- `parseVideo` включить нельзя.

При сборке runtime дополнительно проверяется env: ключи для всего включённого, каталог, принадлежность URI каталогу, корректный `YANDEX_AI_API_URL`. Сетевых запросов при проверке нет — настоящий ключ и квота этой проверкой не подтверждаются.

## Хранение: таблица `ai_config_version`

Миграция [0004_ai_config_version.sql](../../db/migrations/0004_ai_config_version.sql).

| Колонка | Смысл |
| --- | --- |
| `id` | Номер версии |
| `config` | Документ (jsonb) |
| `comment` | Комментарий при сохранении |
| `created_at`, `created_by` | Когда и кто сохранил (`NULL` — скрипт) |
| `is_active` | Активная версия; активна ровно одна (частичный уникальный индекс) |

Защита триггерами (`ai_config_version_guard`): сохранённую версию изменить нельзя (меняется только `is_active`); активную версию удалить нельзя, даже прямым SQL. Старые неактивные версии удалить можно.

## Как сервер получает конфигурацию

[ai-config-store.ts](../../src/server/ai-config-store.ts) (доступ к БД) + [config-store.ts](../../src/server/ai/config-store.ts) (правила):

1. При старте Node.js (`src/instrumentation.ts`) загружается активная версия, строится runtime. Запросы обслуживаются после этого.
2. Каждые 30 секунд — запрос `id` активной версии. Изменился → новая версия загружается, runtime заменяется. Начатые вызовы дорабатывают на прежнем.
3. Runtime хранится на `globalThis`: все части приложения Next.js видят одну конфигурацию.

| Ситуация | Поведение |
| --- | --- |
| Активная версия верна | Работает она |
| Нет активной версии | ИИ выключен, остальная CRM работает |
| БД недоступна при старте | ИИ выключен; при следующей проверке, когда БД ответит, — переход на активную версию |
| Активная версия неверна при старте (нет ключа, чужой каталог…) | ИИ выключен; причина в логе и в «Маршрутах ИИ». Эта версия повторно не собирается (версии не меняются) |
| Новая версия неверна или БД недоступна во время работы | Остаётся последняя рабочая конфигурация; причина в логе |

Ошибка конфигурации **никогда не останавливает приложение**. Сообщения в логе — с префиксом `[ai-config]`, например `using database version 3`, `database version 4 is invalid: …`.

Сохранение через UI проверяет всё заранее, поэтому неверная версия обычно появляется только при изменении env (удалили ключ, сменили каталог) или при правке таблицы вручную.

## «Маршруты ИИ» (Настройки → Модели)

Только для админа платформы. [ai-routing.tsx](../../src/components/blocks/admin-llm-models/ai-routing.tsx), сервер — [admin-llm-routing.ts](../../src/server/admin-llm-routing.ts).

| Часть | Что делает |
| --- | --- |
| Состояние | Что выполняет этот сервер (версия N из БД / ИИ выключен), активная версия, последняя ошибка; адрес API, каталог, наличие ключей (только «✓ / нет») |
| Процессы | Вкл/выкл, модель по умолчанию, разрешённые модели. Выбор модели по умолчанию добавляет её в разрешённые |
| Модели | Вкл/выкл, название, URI, возможности; «Добавить модель» (ID: латиница, цифры, `.`, `-`, `_`); удаление (модель убирается и из процессов) |
| Сервисы, функции, файлы | OCR / SpeechKit / Search API; веб-поиск, чтение сайтов, голосовой ввод; режим изображений, лимиты секунд аудио и страниц PDF |
| Сохранить новую версию | С комментарием. Кнопка активна, когда есть изменения |
| История | Последние 50 версий: дата, автор, комментарий; «Сделать активной» — откат |

Сохранение (`POST /api/admin/llm/routing`): схема → сборка runtime с env этого сервера → в транзакции прежняя версия становится неактивной, новая — активной. Тот же документ, что уже активен, не сохраняется («Нет изменений»). Этот сервер применяет версию сразу, остальные — за ≤ 30 секунд.

Откат (`POST /api/admin/llm/routing/activate`): старая версия сначала проверяется с текущим env; не проходит — ошибка, ничего не меняется.

Ошибки проверки показываются текстом правила без значений полей, например `services.ocr (PDF parsing requires the OCR service)`.

Как добавить новую модель Yandex:

1. Найти URI модели в каталоге моделей Yandex AI Studio (`gpt://<каталог>/<модель>/<версия>`).
2. «Добавить модель» → ID, название, URI, возможности (для чата и аналитики нужны `tools` и `streaming`; для разбора — `structuredOutput`).
3. Включить модель и отметить её в разрешённых у нужных процессов (или сделать моделью по умолчанию).
4. Сохранить с комментарием. Для учёта стоимости — связать модель с позицией прайса в блоке «Цены Yandex» или ввести цену вручную ([ai-usage-and-billing.md](ai-usage-and-billing.md)).

## API

| Маршрут | Метод | Тело / ответ |
| --- | --- | --- |
| `/api/admin/llm/routing` | GET | Состояние сервера, активная версия, документ, история, каталог процессов/возможностей, наличие env |
| `/api/admin/llm/routing` | POST | `{ config, comment? }` → `{ id }` |
| `/api/admin/llm/routing/activate` | POST | `{ id }` → `{ id }` |

Без входа — 401, не админ — 403, ошибка проверки — 400 с текстом.

## Командная строка

Запуск из корня репозитория; env передаётся явно через `--env-file` (файлы `.env` автоматически не читаются).

| Команда | Назначение |
| --- | --- |
| `node --env-file=<env> tools/ai/run.mjs seed --input <file> [--dry-run] [--replace] [--comment text]` | Загрузить документ из JSON-файла в БД как активную версию ([seed.ts](../../tools/ai/seed.ts)). Есть активная версия → остановка, `--replace` — новая версия. `--dry-run` — только проверка. Нужен `DATABASE_URL` |
| `node --env-file=<env> tools/ai/run.mjs check --config <file> [--probe <task>]` | Проверить документ из файла и env без сети; `--probe` — платный синтетический вызов модели ([check.ts](../../tools/ai/check.ts)) |
| `node tools/ai/run.mjs test` | Тесты ИИ-подсистемы, без сети и БД |

Значения env должны совпадать с Secret `crm-env` того стенда, куда пишется версия: проверка идёт по env процесса, который запускает скрипт.
