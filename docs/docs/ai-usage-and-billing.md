# Учёт ИИ, лимиты и цены

Каждый вызов модели записывается в журнал и оценивается в рублях. Для каждой организации действует дневной лимит расходов. Цены моделей приходят из Yandex Billing API автоматически раз в сутки; админ может ввести их вручную. Клиенту показывается цена с наценкой.

Подробная техническая спецификация: [docs/ai/metering-and-billing.md](../ai/metering-and-billing.md).

## Данные

Таблицы из миграции [0003_llm_usage_org_settings.sql](../../db/migrations/0003_llm_usage_org_settings.sql):

| Таблица | Что хранит | Кто пишет |
| --- | --- | --- |
| `llm_usage` | Одна строка на вызов модели: время, организация, процесс (`task`), ID модели и её имя без каталога, `generate` / `stream`, токены вход/выход, `cost_rub`, задержка, успех, класс ошибки, элемент источника. **Без текста запроса и ответа** | Приложение |
| `llm_model_price` | Цена модели: ₽ за 1 000 токенов вход/выход, дата начала действия. `created_by = NULL` — автоматическая цена | Синхронизация цен; админ |
| `platform_setting` | Ключ → jsonb: `llm.dailyCapRub` (лимит по умолчанию), `llm.markupPercent` (наценка), `llm.priceSync.skuMap` (связи с прайсом), `llm.priceSync.lastRun` (последняя синхронизация) | Админ; синхронизация |
| `organization_settings` | На организацию: режим Topics, свой дневной лимит, системный пользователь Topics | Админ |

## Учёт вызова

[usage.ts](../../src/server/ai/usage.ts) оборачивает **каждую** модель, выданную runtime:

1. До вызова — проверка дневного лимита организации. Лимит исчерпан → отказ (`AiBudgetError`), отказ тоже записывается (`error_class = budget_exceeded`).
2. После вызова (для потока — когда он закончился или оборвался) — запись строки в `llm_usage` ([llm-usage.ts](../../src/server/llm-usage.ts)).

Организация вызова берётся из параметра `resolve({ organizationId })` (чат, аналитика, карточки, сделки, заказ из запроса, итоги чата) или из контекста `withAiUsageContext(...)` (разбор источников, загрузки, данные компаний, веб-поиск).

Стоимость `cost_rub` = токены × последняя цена модели с датой начала ≤ времени вызова. Нет цены → `cost_rub = NULL` («нет цены» в UI), такой вызов в лимит не идёт.

Не учитываются: вызовы OCR, SpeechKit и Search API; кэшированные токены и токены инструментов отдельно не оцениваются. Учёта по пользователю нет.

## Дневной лимит

- Лимит организации: свой (`organization_settings.llm_daily_cap_rub`), иначе общий (`llm.dailyCapRub`), иначе 500 ₽.
- День — календарный по Москве.
- Считается по себестоимости (`cost_rub`), без наценки.
- Вызовы без организации не ограничиваются.
- Не удалось прочитать БД при проверке → вызов разрешается (лимит — защита расходов, а не безопасности).
- Фоновый разбор источника при исчерпанном лимите не падает: элемент остаётся в очереди до следующего запуска.

## Цены моделей

### Автоматически из Yandex Billing API

[billing.ts](../../src/server/ai/billing.ts) (без БД) + [llm-pricing.ts](../../src/server/llm-pricing.ts):

- **Доступ**: сервисный аккаунт с ролью `billing.accounts.viewer` на платёжном аккаунте; его авторизованный ключ (JSON, base64 в одну строку) → `YANDEX_BILLING_SA_KEY`, ID платёжного аккаунта → `YANDEX_BILLING_ACCOUNT_ID`. API-ключ Billing API не принимает: приложение получает IAM-токен по JWT (PS256).
- **Прайс**: позиции (SKU) сервиса AI Studio, отдельно входные и выходные токены; договорная цена важнее публичной; единицы приводятся к ₽ за 1 000 токенов.
- **Связь модели с прайсом**: встроенные связи (`yandexgpt-5.1`, `qwen3.6-35b-a3b`, синхронный режим) и связи, заданные админом. Модель без связи получает цену только вручную.
- **Расписание**: таймер в каждом процессе приложения — первая проверка через 2 минуты после старта, затем каждые 6 часов; синхронизация, если последняя успешная была более 23 часов назад. Неудачная повторяется через 6 часов. Реплики не создают дубли (блокировка в БД + «цена изменилась» + уникальный индекс).
- **Новая строка цены** добавляется, только если цена изменилась, и для объявленных будущих изменений цены.
- Переменные не заданы → синхронизация выключена, цены вводятся вручную.

### Вручную

«Модели → Цены моделей (₽ за 1 000 токенов)»: модель, вход/выход ₽ за 1 000 токенов, «Действует с». Цены не редактируются: новая цена — новая строка. Источник в таблице: «авто (Yandex)» или «вручную».

### Наценка

`llm.markupPercent`, по умолчанию 50 %, диапазон 0–1000 %. Только для показа: «Для клиента, ₽» = себестоимость × (1 + наценка / 100). На лимит и `cost_rub` не влияет.

## Интерфейс (Настройки, только админ платформы)

**«Использование»** — блок «Статистика использования» ([usage-stats.tsx](../../src/components/blocks/admin-llm-models/usage-stats.tsx)):

- Период: сегодня, 7, 30, 90 дней (до 92 дней).
- Группировка: день, организация, процесс (русские названия), модель.
- Итоги: вызовы, ошибки, отказы по лимиту, токены вход/выход, себестоимость, «Для клиента (+N %)»; средняя и p95 задержка в таблице; вызовы без цены.

**«Модели»** ([admin-llm-models.tsx](../../src/components/blocks/admin-llm-models.tsx)):

1. «Маршруты ИИ» — [ai-configuration.md](ai-configuration.md).
2. «Цены Yandex (автоматически)» — «Обновить цены», результат последней проверки (добавленные цены, ошибки), связь каждой модели с позицией прайса.
3. «Цены моделей (₽ за 1 000 токенов)» — таблица цен, ручное добавление, наценка, цена для клиента.
4. «Лимиты и Темы по организациям» — общий лимит, свой лимит организации, режим Topics, расход за сегодня.

## API (только админ платформы)

| Маршрут | Методы | Назначение |
| --- | --- | --- |
| `/api/admin/llm/stats?from=&to=` | GET | Строки по (день МСК, организация, процесс, модель) |
| `/api/admin/llm/settings` | GET, PUT | Общий дневной лимит, наценка |
| `/api/admin/llm/orgs` | GET, PUT | Режим Topics и лимит организации, расход за сегодня |
| `/api/admin/llm/prices` | GET, POST, DELETE `?id=` | Цены моделей |
| `/api/admin/llm/price-sync` | GET, POST | Состояние синхронизации; запуск сейчас |
| `/api/admin/llm/sku-links` | GET, PUT | Позиции прайса; связь модели с позицией |
