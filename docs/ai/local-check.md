Конфигурация хранится в БД и меняется в «Настройки → Модели → Маршруты ИИ»: [config-in-db-spec.md](config-in-db-spec.md). Ниже — описание на момент написания.

После этапа 2 серверная конфигурация применяется к действующим AI-функциям. Подробная инструкция по окружению, синтетическим probes и проверке UI: [stage-2-check.md](stage-2-check.md).

## Без ключей и сети

Из корня проекта:

```bash
node tools/ai/run.mjs check --config config/ai/blocked.json
node tools/ai/run.mjs test
```

Blocked-профиль показывает `disabled` для всех задач. Тесты используют подменённый HTTP transport и синтетические ключи.

Проверка отказа:

```bash
node tools/ai/run.mjs check --config config/ai/blocked.json --probe chat
```

Ожидается код завершения 1 без запроса провайдеру.

## Профиль приложения

`AI_CONFIG_PATH` обязателен. Для Yandex используйте `config/ai/yandex.json`. Профиль старого Gateway (`legacy.json`) и сам адаптер Gateway удалены (только Yandex). Отсутствие конфигурации не включает Gateway по умолчанию. После изменения настроек перезапустите процесс и обновите вкладки браузера.

CLI читает окружение процесса и не загружает `.env.local` автоматически. Ключи можно передавать из внешнего shell-файла в собственном терминале, как описано в [локальном запуске на Mac](../deploy/local-run.md). Next.js в приложении сохраняет штатную загрузку `.env*`.

На этапе 1 переключатели применялись только к тестовому runtime; эта граница устранена на этапе 2. Состояние реализации и ограничения проверок записаны в [roadmap](roadmap.md).
