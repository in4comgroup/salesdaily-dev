# План перехода на конфигурируемую AI-инфраструктуру

Статус: архитектурный план уточнён под Yandex AI Studio. Этапы 1 и 2 реализованы; протокольные проверки выполнены локально, проверка реального Yandex-каталога и переключение окружений ещё не выполнены. Документация проверена 8 ноября 2026 года.

Основание: [текущие AI-интеграции](current.md).

Прогресс по функциям, причины временных отключений и условия их восстановления ведутся в отдельном [roadmap.md](roadmap.md). Пользователь разрешил временное отключение неподдерживаемых функций при обязательной фиксации причины. Реестр обновляется вместе с изменением маршрута или доступности; планируемое отключение не обозначается как выполненное.

## Цель

Подключить Yandex AI Studio для обработки AI-запросов, сохранив существующие интеграции как конфигурируемые варианты. Включать и выключать подключения, модели и функции через серверную конфигурацию без изменения бизнес-кода.

Зафиксированные требования пользователя: обязательная платформа — Yandex AI Studio; данные не должны уходить за пределы региона. В этом плане целевой регион принят как РФ по контексту выбранной платформы; это предположение нужно подтвердить до production-переключения. Для рабочего развёртывания старые внешние маршруты запрещены, в том числе как fallback. Их сохранение в коде позволяет использовать их в иных разрешённых средах, но не передавать им данные этого развёртывания.

Конфигурация должна обеспечивать соблюдение утверждённых ограничений на передачу данных. Само наличие регионального адреса API не подтверждает юридическое соответствие: требования и допустимость инфраструктуры должны быть установлены отдельно.

## Что нужно уточнить перед подключением нового провайдера

- Применимые юрисдикции и утверждённые требования к обработке данных.
- Подтверждение целевого региона РФ; каталог Yandex Cloud, доступные модели, квоты и учётные данные.
- Точный охват запрета: обработка и хранение, сетевой транзит, обращения пользователей из-за рубежа. До уточнения не разрешать дополнительные внешние маршруты.
- Условия хранения запросов и ответов, журналирования, использования данных для обучения, доступа поддержки и привлечения субподрядчиков.
- Применяются ли ограничения ко всему развёртыванию или различаются между организациями.
- Нужны ли изменения конфигурации без перезапуска. Для первой версии предлагается файл конфигурации с перезапуском приложения.

План описывает техническую архитектуру, а не заключение о соответствии законам. Для Yandex выбран прямой адаптер API, а конкретные модели и режим API должны пройти проверку совместимости.

## Уточнения по Yandex AI Studio

### Прямой маршрут и API

Yandex предоставляет Chat Completions и Responses API; для интеграции предлагается сохранить AI SDK и использовать явный адаптер с адресом Yandex. OpenAI-совместимость — формат протокола, она не требует отправки данных в OpenAI. См. [обзор API](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/api).

Базовый адрес для API по потреблению: `https://ai.api.cloud.yandex.net/v1`. Подключение требует API-ключ сервисного аккаунта либо IAM-токен и идентификатор каталога. Заголовок авторизации и передача каталога зависят от API; адаптер должен формировать их явно, не полагаться на значения SDK по умолчанию. Для обновляемого IAM-токена нужна автоматическая ротация. См. [аутентификацию](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication).

Рабочий кандидат — Chat Completions с явной передачей истории из приложения; Responses рассматривается отдельно при необходимости. Выбор закрепить после проверки tools, streaming и structured output на доступных моделях. Не переносить управление CRM-инструментами в облачных агентов на первом этапе.

### Регион и хранение

В [разделе безопасности Yandex](https://aistudio.yandex.ru/ru/security) заявлено размещение моделей Model Gallery и компонентов AI Studio в РФ. Это основание для выбора платформы, а не доказательство отсутствия внешних обращений у наших инструментов. Перед запуском подтвердить применимость условий к используемым сервисам и зафиксировать их для выбранного облака.

Передавать `x-data-logging-enabled: false` для модельных запросов: эта настройка отключает использование содержимого для улучшения сервиса. См. [отключение логирования](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging).

По [политике хранения](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage) этот заголовок не отключает API-хранилища и трейсинг. Для Responses задавать `store: false`; не использовать `previous_response_id` и Conversations в первой версии. Трейсинг оставить выключенным. Асинхронные OCR/STT и загружаемые файлы требуют отдельного учёта сроков и удаления.

### Карта замены

| Текущая функция | План для регионального развёртывания |
| --- | --- |
| Чат, аналитика, карточки, сделки, заказы, сохранение переписки | Текстовые модели Yandex AI Studio через прямое подключение; модель для каждой задачи выбирается конфигурацией |
| Текстовые парсеры и атрибуция | Текстовая модель через тот же resolver |
| Изображения и PDF | Проверить доступную мультимодальную модель; при необходимости Vision OCR / локальное извлечение текста, затем LLM |
| Аудио и голосовой ввод | Проверить SpeechKit, включая требования к определению говорящих; browser SpeechRecognition отключить |
| Видео | Проверить нативную поддержку; альтернативно локальное извлечение кадров и аудио → разрешённые OCR/STT/LLM; до проверки функция выключена |
| Веб-поиск и исследование компаний | Google Search выключить; кандидат на замену — Yandex Search API после проверки границ обработки и состава запросов |
| Прямое чтение сайтов компаний | По умолчанию выключить: произвольный сайт и его редиректы могут находиться за пределами региона |

SpeechKit, Vision OCR и Search API — кандидаты внутри экосистемы Yandex, а не уже проверенные замены. Для каждого нужен отдельный технический и региональный допуск. Географический фильтр поисковой выдачи не считается ограничением места обработки данных.

## Целевая архитектура

```text
Функция приложения / API / фоновая обработка
                   ↓
Серверный resolver: задача + контекст организации + выбранная модель
                   ↓
Проверка политики, enabled и возможностей
                   ↓
Явный адаптер подключения
                   ↓
Разрешённая инфраструктура и модель
```

Сохранить Vercel AI SDK как интерфейс генерации на первом этапе, если новый API позволяет это сделать. Не смешивать замену маршрутизации с заменой UI или полным переписыванием генерации.

### Подключения

Подключение определяет способ обращения к инфраструктуре:

- стабильный внутренний `id`;
- `enabled`;
- тип адаптера: существующий Vercel Gateway, совместимый API или специфический SDK нового провайдера;
- серверный `baseUrl`, если применимо;
- ссылки на секреты окружения;
- таймауты, повторы и ограничения параллелизма;
- сведения об инфраструктуре для проверки утверждённой политики.

Одна и та же модель через Vercel Gateway и через другое подключение — разные маршруты с разной допустимостью. Название модели не определяет место обработки.

### Модели

Запись модели связывает пользовательское имя с конкретным подключением и upstream model ID:

- стабильный внутренний `id`;
- `label`, `enabled`;
- `connectionId` и `upstreamModelId`;
- проверенные возможности: текст, structured output, tools, streaming, изображения, PDF, аудио, видео;
- проверенные ограничения входа и параметры генерации.

Совместимость API по формату не означает поддержку всех этих возможностей. Реестр отражает проверенные возможности конкретного маршрута.

### Назначения по функциям

Для каждой задачи задаются `enabled`, модель по умолчанию, список разрешённых моделей и необязательные резервные маршруты:

- `chat`;
- `analytics`;
- `cards`;
- `deals`;
- `orderRequest`;
- `chatSummary`;
- `companyResearch`, `companyExtraction`;
- `parseText`, `parsePdf`, `parseImage`, `parseAudio`, `parseVideo`, `parseOffice`;
- `orgAttribution`.

Веб-поиск настраивается отдельно: доступность, провайдер поиска и, если нужен, маршрут модели для исследования. Голосовой ввод браузера также должен иметь отдельный переключатель.

### Политика развёртывания

Политика задаёт разрешённые подключения и внешние возможности. Ограничения политики имеют приоритет над `enabled` у модели и задачи.

- По умолчанию неизвестные подключения и маршруты запрещены.
- Нет неявного переключения на Vercel или другого внешнего провайдера при ошибке.
- Каждый резервный маршрут проходит те же проверки.
- Вложенные вызовы поиска, исследования и извлечения проходят через тот же серверный слой.
- Проверки применяются к API, фоновым заданиям и ручным действиям.
- При отсутствии разрешённого маршрута функция возвращает понятную ошибку или отключается; данные не отправляются по альтернативному адресу.

Для первой версии — политика на уровне развёртывания. Если нужны ограничения по организациям, добавить серверное сужение общей политики; организация не может разрешить маршрут, запрещённый развёртыванием. Контекст организации берётся из доверенного серверного контекста, а не из модели или запроса клиента.

## Действующая конфигурация

Реализованы строгие JSON-профили:

- `config/ai/blocked.json` — запрет всех AI-задач.
- `config/ai/legacy.json` — существующие провайдеры через явный Vercel Gateway. Удалён 11 ноября 2026 года вместе с адаптером Gateway (только Yandex).
- `config/ai/yandex.json` — прямой Yandex для текстовых задач, остальные возможности выключены.

Фактическая схема находится в `src/server/ai/config.ts`. Подключение Yandex содержит `enabled`, `adapter`, фиксированный `baseUrl`, ссылки `credentialsEnv` и `folderIdEnv`; запись модели — `upstreamModelIdEnv` с полным model URI. Адрес, схема авторизации и обязательное отключение логирования в адаптере не меняются произвольными заголовками конфигурации.

Политика использует `allowedConnections` и `features` (`webSearch`, `websiteFetch`, `browserSpeechRecognition`). Каждая задача задаёт `enabled`, `defaultModel`, `allowedModels` и пустой `fallbackModels`. Непустые fallback пока отвергаются. Отсутствующая задача запрещена.

В Yandex-профиле capabilities описывают ожидаемую поддержку текста, structured output, tools и streaming; реальную совместимость выбранного model URI нужно подтвердить probes. Мультимодальные capabilities для Yandex на этом этапе отвергаются: их реализация относится к этапу 3.

Секреты хранятся в окружении / Kubernetes Secret. Серверный JSON монтируется через ConfigMap, применяется после перезапуска; схема проверяется при старте Node.js runtime. Каталог UI получает только безопасную проекцию.

Локальные шаги: [stage-2-check.md](stage-2-check.md). Настройка кластера: [ai-configuration.md](../deploy/ai-configuration.md).

## Этапы реализации

### 1. Зафиксировать требования и матрицу возможностей

Получить сведения об обязательной инфраструктуре и утвердить допустимые маршруты. Составить матрицу задач, типов данных, поддерживаемых форматов и запрещённых внешних обращений. Для неподдерживаемых задач выбрать отключение или отдельный разрешённый сервис OCR/STT/обработки видео.

Результат: утверждённая политика и требования к адаптеру. На этом этапе проверяются актуальные документы выбранного провайдера и применимые требования.

### 2. Ввести конфигурацию и серверный resolver

Предлагаемые модули: `src/server/ai/config.ts`, `policy.ts`, `registry.ts`, `resolve.ts`, `adapters/`. Схема конфигурации — Zod. Все адреса и секреты доступны только серверу.

Resolver принимает задачу, доверенный контекст и необязательный внутренний ID модели; возвращает явный объект модели SDK и допустимые параметры. Клиент не передаёт `baseUrl`, upstream ID или ключ.

Перенести существующий Vercel-маршрут в явный адаптер. Зарегистрировать текущие Gemini, GPT и Claude без удаления интеграций. Старые внутренние ключи при необходимости поддержать через явную таблицу соответствий с проверкой политики.

Результат: существующее поведение воспроизводится разрешённой конфигурацией, некорректная конфигурация отвергается до запросов.

Инфраструктурная часть реализована как этап 1 roadmap: `src/server/ai/`, примеры `config/ai/`, CLI и тесты `tools/ai/`. Локальная проверка описана в [local-check.md](local-check.md). Runtime валидирует конфигурацию при создании; на этапе 2 проверка подключена к запуску приложения, вызовы переведены на resolver. На этапе 1 резервные маршруты не поддерживаются, непустой `fallbackModels` отвергается.

### 3. Провести все вызовы через resolver

Перенести чат, аналитику, карточки, сделки, разбор заказов, сохранение чата, обогащение компаний и все парсеры. Убрать передачу строк моделей непосредственно в SDK за пределами адаптеров, чтобы не оставалось неявного маршрута через Gateway.

Разделить настройки моделей парсеров и остальные настройки `parser-config.ts`: форматы, ограничения размеров и предобработка могут остаться в существующем модуле.

Результат: любой AI-вызов, включая cron и вложенные исследования, проверяет одну политику.

### 4. Сделать интерфейс зависимым от серверной конфигурации

Добавить серверную выдачу безопасного каталога доступных моделей для конкретной задачи и контекста. Каталог содержит внутренний ID, подпись и необходимые UI-признаки; адреса и секреты не выдаются.

Обновить выбор моделей в чате, диалогах карточек и сделок. Кнопки без выбора модели используют разрешённый default своей задачи. Устаревший выбор клиента не обходит серверную проверку. Выключенные функции показывают понятное состояние недоступности.

Результат: изменение серверной конфигурации управляет реальной доступностью и интерфейсом.

### 5. Подключить обязательную инфраструктуру

Реализовать прямой адаптер Yandex AI Studio. Выбрать доступные model URI из каталога заказчика и закрепить проверенную версию/вариант модели, если сервис это позволяет. Проверить на синтетических данных текст, JSON по схеме, потоковую выдачу, tools, ошибки, отмену и таймауты. Проверить заголовки авторизации, каталога, отключения логирования и отсутствие запросов в Vercel/OpenAI. Отдельно проверить русский язык и каждый необходимый тип файла.

Если модель не поддерживает аудио/видео/PDF, предусмотреть явный разрешённый конвейер предобработки; не заменять его скрытым внешним вызовом.

Результат: подтверждённая матрица возможностей нового подключения.

### 6. Отделить веб-поиск и голосовой ввод

Сохранить Google Search как отключаемую реализацию; запретить его в целевом развёртывании. Проверить Yandex Search API как замену. Применить настройки как к `web-search.ts`, так и к исследованию компаний в `clients.ts`, включая прямое чтение сайтов. До проверки все эти внешние возможности выключены.

При отключении поиска исключить соответствующий инструмент из чата и скорректировать промпт. Обогащение компаний не должно отправлять запросы в старый поиск. Проверить, какие данные включаются в поисковый запрос.

Браузерный SpeechRecognition отключить в целевом развёртывании; кандидат на замену — серверная интеграция SpeechKit после проверки API и региона.

Результат: выбранная региональная модель не вызывает неразрешённые сервисы косвенно.

### 7. Проверить маршруты и переключить окружение

На тестовом развёртывании включить строгую политику и проверить все задачи. Использовать синтетические либо отдельно разрешённые данные; не дублировать реальные запросы старому провайдеру для сравнения без разрешения на такую передачу.

Записывать технические метаданные: задачу, внутренний ID модели, подключение, версию конфигурации, время, статус и расход токенов при наличии. Не записывать промпты, ответы и ключи по умолчанию; проверить существующие error-логи и трассировку на содержимое запросов.

Где позволяет инфраструктура, дополнить программную политику ограничениями исходящего трафика. Проверить доступные механизмы контроля доменов/IP и редиректов; обычная NetworkPolicy не предполагается автоматически поддерживающей доменные правила. Проверить также самопроизвольные fallback и внешнюю обработку на стороне нового провайдера.

После успешной проверки переключить production-конфигурацию. Обновить документацию окружения и эксплуатации. Rollback допускается только на конфигурацию, соответствующую той же политике; старый внешний маршрут не становится допустимым из-за аварии.

## Проверки при приёмке

- Выключенная модель отсутствует в каталоге и отвергается сервером при прямом запросе.
- Подключение вне allowlist не используется при обычном вызове, вложенном вызове, retry или fallback.
- Ошибочная конфигурация не приводит к использованию SDK Gateway по умолчанию.
- Для всех существующих AI-точек задан явный маршрут либо явное отключение.
- Проверены структурированные ответы и реальные сценарии tools, streaming и мультимодальности на новом API.
- При отключённом веб-поиске нет обращений к Google Search из чата и обогащения компаний.
- Проверены голосовой ввод, прямое чтение сайтов, фоновые задания, логи и трассировка.
- Текущие интеграции остаются в коде и могут включаться только в средах, где разрешены политикой.
- Конфигурацию можно изменить без редактирования бизнес-кода; для первой версии требуется перезапуск приложения.
- Подтверждены фактические места обработки и условия провайдера; включение маршрута не основано только на самостоятельно заданной метке региона.
- В региональном профиле разрешён только прямой маршрут Yandex; сохранённые Vercel/GPT/Claude/Gemini маршруты не принимают данные даже при ошибках Yandex.
- Проверено отключение логирования содержимого, отсутствие включённого трейсинга и серверного хранения Responses/Conversations там, где оно не требуется.
- Исходящий трафик проверен для всех вспомогательных функций; запрет касается также URL, редиректов, OCR/STT, телеметрии и повторных попыток.

## Границы работ

В этот план входит управление AI-маршрутами. Nylas, Google Drive/Chat, почта, хранилище и остальные внешние интеграции требуют отдельной оценки, если цель распространяется на соответствие всей CRM. Перенос AI сам по себе не подтверждает соответствие всего приложения.

Не входят в первую версию: админский редактор конфигурации в БД, горячее переключение, собственный универсальный AI-прокси и переписывание интерфейса генерации. Эти решения можно добавить при подтверждённой необходимости.

## Реализация этапа 3

Маршруты файлов, SpeechKit и Yandex Search API реализованы, реальная приёмка отложена до стенда. Основной Yandex JSON остаётся один; CLI `profile` генерирует конфигурацию развёртывания с выбранными функциями. Определение говорящих, прямое чтение сайтов, браузерный SpeechRecognition и вложения глобального чата остаются отключёнными; видео и неподдерживаемые аудиоформаты временно выключены. PDF обрабатывается прямым Vision OCR, поддерживаемое аудио — прямым SpeechKit; Poppler и ffmpeg удалены. Это явные ограничения, а не подтверждённая эквивалентность прежних функций. Права, ключи, ограничения обработки/удаления и приёмка: [stage-3-check.md](stage-3-check.md).
