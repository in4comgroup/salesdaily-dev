## Одна конфигурация

Основной файл — `config/ai/yandex.json`. Runtime читает один JSON из `AI_CONFIG_PATH`, без объединения файлов. Экспериментальный `yandex-media.json` удалён. По умолчанию новые задачи и сервисы выключены, текстовые функции остаются включёнными.

Подготовка конфигурации стенда из корня проекта:

```bash
node tools/ai/run.mjs profile \
  --input config/ai/yandex.json \
  --output deploy/k8s/app/ai-config.json \
  --enable images,pdf,audio,search,voice
```

Команда перезаписывает только указанный JSON, не читает ключи и не меняет кластер. Это генерация копии из одного исходника для штатного workflow. `--enable` — **полный** список функций этапа 3. Например, `--enable pdf,audio,voice` оставит изображения/поиск выключенными и не потребует vision-модели/ключа поиска. Пустой список возвращает только текстовые функции.

`video` больше не поддерживается этой командой: она явно отклоняет такую попытку, а не молча пропускает флаг. Если ранее сформирован JSON с `pdf=vision`, `video=frames-speechkit` или `videoFrames`, пересоздайте его из обновлённого исходника — прежняя схема локальной обработки больше не принимается.

| Функция | Переключатели при ручном редактировании |
| --- | --- |
| Изображения | `tasks.parseImage.enabled`, `tasks.describeImage.enabled`, `models.yandex-vision.enabled`; `files.images=vision` |
| PDF | `tasks.parsePdf.enabled`, `services.ocr=true`. Vision-модель не требуется |
| Аудио | `tasks.parseAudio.enabled`, `services.speech=true` |
| Поиск / исследование компаний | `services.search=true`, `features.webSearch`, задачи `webSearch`, `companyResearch`, `companyExtraction` |
| Микрофон | `features.serverSpeechRecognition`, `services.speech=true`; задача `parseAudio` отдельно не обязательна |
| Видео | `tasks.parseVideo.enabled=false` всегда (схема не позволяет включить) |

Поля приведены для схемы версии 2 (11 ноября 2026 года); до этого были `policy.features`, `services.*.enabled` и `preprocessing`.

Модели по-прежнему выбираются через `defaultModel` / `allowedModels`. После изменения JSON/env требуется перезапуск.

## Ключи и права

В **полный внешний env-файл** для `crm-env` добавить значения только для включённых функций:

```dotenv
YANDEX_AI_VISION_MODEL_URI=gpt://<тот-же-folder-id>/qwen3.6-35b-a3b
YANDEX_OCR_API_KEY=<секретный-ключ-OCR>
YANDEX_SPEECH_API_KEY=<секретный-ключ-SpeechKit>
YANDEX_SEARCH_API_KEY=<секретный-ключ-Search-API>
```

Существующие `YANDEX_AI_API_KEY`, `YANDEX_AI_FOLDER_ID`, `YANDEX_AI_TEXT_MODEL_URI` остаются. Vision использует ключ AI, остальные сервисы — свои явно указанные переменные; каталог берётся из подключения Yandex. Можно записать один ключ в несколько переменных, если у него и аккаунта есть необходимые права. Автоматической подстановки AI-ключа нет.

| Сервис | Права |
| --- | --- |
| Изображения | Доступ к мультимодальной модели; пример URI из [документации Yandex](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/multimodels-request) |
| PDF / Vision OCR | Роль `ai.vision.user`; в актуальном [примере PDF](https://aistudio.yandex.ru/ru/docs/vision/operations/ocr/text-detection-pdf) указана область ключа `yc.ai.foundationModels.execute` |
| SpeechKit | Роль `ai.speechkit-stt.user`, область `yc.ai.speechkitStt.execute`; проверить [доступ](https://aistudio.yandex.ru/ru/docs/ai-studio/security/) |
| Search API | Роль `search-api.webSearch.user`, область `yc.search-api.execute`; [инструкция](https://aistudio.yandex.ru/ru/docs/search-api/operations/web-search-sync) |

Проверить права аккаунта **и** область ключа в своём каталоге. Ключи не отправлять в переписку.

Обновление Secret из полного файла (сохранить БД, auth, шифрование, почту, S3 и остальные параметры):

```bash
kubectl config current-context
kubectl -n salesdaily create secret generic crm-env \
  --from-env-file=/путь/к/полному/crm-env \
  --dry-run=client -o yaml |
kubectl -n salesdaily apply -f -
```

Shell-файл для `source` и env-файл для kubectl имеют разные правила кавычек; подробности в [ai-configuration.md](../deploy/ai-configuration.md). Файл только с новыми ключами для обновления полного Secret не использовать.

## Развёртывание

1. Сгенерировать JSON указанной командой. Проверить diff: только разрешённое подключение Yandex; `websiteFetch=false`, `browserSpeechRecognition=false`, видео выключено.
2. Обновить Secret. Собрать и развернуть **новый образ с новым кодом** штатными workflow. Системные Poppler, ffmpeg, ffprobe и дополнительные шрифты образу больше не нужны. На Mac для браузерной проверки ничего из этого устанавливать не требуется.
3. Не выполнять локальный `apply -k` с неподтверждённым image tag: можно откатить приложение. Изменение только ConfigMap/Secret требует перезапуска Deployment, как описано в [ai-configuration.md](../deploy/ai-configuration.md).
4. Проверить rollout и открыть `/api/ai/config`: нужные задачи видны, `parseVideo` отсутствует среди доступных моделей, `serverSpeechRecognition=true` при включённом микрофоне. Проверить обычный чат.
5. На HTTPS-стенде проверить загрузку `/ai/pcm-recorder.js` без 404: это локальный браузерный модуль записи, он поставляется в `public/` вместе с приложением.

CLI/TypeScript tooling в standalone-образе может отсутствовать. Проверки на стенде выполняются через интерфейс. Для локальной проверки конфигурации можно загрузить env из внешнего файла и выполнить `node tools/ai/run.mjs check --config deploy/k8s/app/ai-config.json` **без `--probe`**: это не вызывает провайдера и не читает пользовательские файлы.

## Маршруты и изменения поведения

| Формат | Обработка |
| --- | --- |
| PNG/JPEG | Исходные байты Base64 → мультимодальная модель → текстовая схема метаданных. До 5 MiB исходного файла; тип проверяется по сигнатуре |
| PDF | Исходный PDF Base64 → Vision OCR async, модель `page` → распознанный текст всех страниц → текстовая схема. До **10000000 байт**. Нет растеризации, временных файлов, Poppler и дополнительной vision-модели |
| WAV | PCM 16-bit WAV напрямую → SpeechKit async `general` → текстовая схема. Размер и длительность PCM проверяются до отправки |
| MP3 / OGG Opus | Исходные байты напрямую → SpeechKit с соответствующим `containerAudioType`; без перекодирования. Длительность берётся из `audioCursors.receivedDataMs` результата, включая тишину, а не из последней реплики |
| Микрофон | Web Audio / AudioWorklet захватывает PCM на устройстве, браузер формирует mono WAV 16 kHz → наш аутентифицированный API → SpeechKit. Нет MediaRecorder/WebM/M4A, внешних кодеков и серверного ffmpeg |
| Видео | Временно выключено в Yandex. Нет подтверждённого прямого входа видео у подключённых API; извлечение кадров/аудио удалено. Legacy-вызовы сохраняются только в явно разрешённом профиле |
| Поиск | Search API v2 sync → до 6 XML-сниппетов → Yandex LLM. Найденные страницы напрямую не скачиваются |

PDF теперь является **OCR текста**, а не визуальным описанием каждой страницы: фотографии, диаграммы без надписей и другие нетекстовые детали могут не попасть в результат. Таблицы/порядок чтения требуют ручной проверки; модель не должна выдумывать недостающие данные. Документ без читаемого текста отвергается. Это изменение возможностей явно учитывается при приёмке.

`pdfMaxPages` по умолчанию 10 (1–20), общий текст до 120000 символов. Без локального PDF-парсера число страниц проверяется **по полному ответу OCR**, после обработки и возможного списания оплаты. Лишние страницы не обрезаются молча. Проверяются непрерывная нумерация с нуля и отсутствие дублей; полнота исходного документа опирается на контракт завершённой операции Yandex.

Аудио штатного парсера — до 10 MiB; `maxMediaSeconds` по умолчанию 180 (1–600). Для MP3/OGG длительность проверяется **после распознавания**, поэтому сверхлимитный файл может быть оплачен, хотя результат будет отклонён. WAV с заголовком неподдержанного кодека отвергается; допускается PCM 16-bit. **M4A, WebM, FLAC, OGG Vorbis и другие форматы в Yandex-профиле не конвертируются и явно отклоняются.** Поддержка старого профиля не расширяет возможности нового.

Микрофон: HTTPS и AudioWorklet, проверить Chrome/Safari. Запись до 90 секунд, WAV до 8 MiB; сервер допускает до 91 секунды для завершения последнего аудиоблока. Вход этой ручки — только PCM WAV. Одновременно один запрос на пользователя в процессе приложения; это не распределённый rate limiter. При отказе записи/разрешений нет перехода к браузерному SpeechRecognition.

Транскрипт/таймкоды сохраняются из SpeechKit и не заменяются ответом LLM. Говорящие — `Unknown`; при наличии речи `speakerCount=null`, а не выдуманное число участников.

## Адреса и хранение

- Модели: `https://ai.api.cloud.yandex.net/v1/chat/completions`.
- PDF: `https://ai.api.cloud.yandex.net/ocr/v1/recognizeTextAsync`, затем `getRecognition?operationId=...`.
- SpeechKit: `https://stt.api.cloud.yandex.net/stt/v3/recognizeFileAsync`, `getRecognition`, `deleteRecognition`.
- Проверка операций: `https://operation.api.cloud.yandex.net/operations/<id>`.
- Поиск: `https://searchapi.api.cloud.yandex.net/v2/web/search`.

Адреса фиксированы кодом, редиректы запрещены, заголовок `x-data-logging-enabled: false` сохраняется. Файлы передаются inline, не как URL для скачивания. Содержимое ошибок провайдера не выводится. Наш сервер не создаёт временные файлы предобработки: данные находятся в памяти запроса. Хранение оригиналов/результатов в CRM остаётся существующим поведением приложения.

SpeechKit удаляет результат в `finally` после получения ID; сбой удаления — ошибка с безопасным ID для администраторской очистки. Аварийное завершение или потеря ответа старта могут оставить результат. Удаление результата не гарантирует отмену ещё выполняющейся операции.

**Для OCR автоматическое удаление результата не реализовано:** в [справочнике TextRecognitionAsync](https://aistudio.yandex.ru/ru/docs/vision/ocr/api-ref/TextRecognitionAsync/) документированы Recognize и GetRecognition, отдельный DeleteRecognition не найден. Не применять SpeechKit DELETE к OCR. Условия/срок хранения асинхронных OCR-результатов проверить с Yandex перед обработкой реальных данных; отключение логирования не является гарантией немедленного удаления результата. Программный выбор адреса также не подтверждает сам по себе регион и договорные условия — это проверка этапа 4.

Таймауты приложения: OCR 120 сек.; SpeechKit-конвейер 150 сек.; vision и финальное структурирование по 60 сек.; поиск со сводкой 60 сек. Длинные задания требуют отдельной фоновой обработки.

## Приёмка на стенде

По одному тестовому материалу без клиентских данных, без пакетного запуска/cron. Результаты записывать в [roadmap.md](roadmap.md).

| Проверка | Ожидание |
| --- | --- |
| PNG/JPEG с русскими надписями/числами | Правильный текст, язык и метаданные |
| Текстовый PDF, скан, многостраничный PDF | Все распознанные страницы по порядку; числа, таблицы и полнота сверены вручную |
| PDF с картинками без текста | Не выдаёт выдуманное описание; явное ограничение OCR учтено |
| PDF > 10 млн байт / > pdfMaxPages | Ошибка, нет успешного результата по первым страницам; учесть возможную оплату OCR при проверке числа страниц |
| WAV, MP3 и OGG Opus | Транскрипт и таймкоды совпадают с записью; тишина не теряется из длительности |
| M4A / WebM / Vorbis | Явный отказ, нет локальной конвертации и другого провайдера |
| Микрофон Chrome/Safari | HTTPS, разрешение микрофона, фраза → текст в поле чата, без автоматической отправки сообщения |
| Отказ микрофона/нет AudioWorklet | Понятная ошибка, без внешнего браузерного STT |
| Видео | Отказ до отправки данных в AI, задача выключена в каталоге |
| Поиск и компания | Реальные URL из Yandex; неподтверждённые поля пустые; сайты напрямую не читаются |
| Неверные права/отключённая функция | Ошибка без fallback на другой API; в логах нет ключей/содержимого |
| Возврат к текстовому набору | Генерация с пустым `--enable`, обновление ConfigMap и перезапуск; чат работает, новые функции выключены |

Остаются отключёнными: видео, неподдерживаемые аудиоконтейнеры, определение говорящих, прямое чтение сайтов, браузерный SpeechRecognition и вложения глобального чата. Возврат — только после отдельной разрешённой интеграции и приёмки, без скрытого внешнего провайдера.

## Проверки разработчика

Протокольные тесты используют mock HTTP; для браузерного WAV проверяется контейнер/длительность, а для AudioWorklet — смешивание каналов и завершение последнего блока. Проверяются прямые байты/типы контейнеров, OCR-страницы и ошибки, отсутствие decoder/fallback, удаление STT. Реальные API, браузеры и production Docker build ещё не запускались.
