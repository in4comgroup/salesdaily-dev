# Исходные AI-интеграции до перехода

Это снимок исходного состояния до этапов 1–2. Действующая конфигурация и статус переноса описаны в [stage-2-check.md](stage-2-check.md) и [roadmap.md](roadmap.md).

Описание составлено по коду проекта 8 ноября 2026 года. Фактические запросы работающего сервера не перехватывались; значения production-секретов не проверялись.

## Общая схема

Почти все AI-функции используют общий маршрут:

```text
Интерфейс / фоновая обработка
          ↓
Next.js сервер → Vercel AI SDK
          ↓
Vercel AI Gateway
          ↓
Google Gemini / OpenAI / Anthropic
```

Для замены нужно рассматривать отдельно обычные LLM-вызовы, обработку файлов и веб-поиск. Смена модели в чате не заменяет остальные интеграции.

## Модели

Общий справочник моделей: [`src/lib/llm-models.ts`](../../src/lib/llm-models.ts).

| Модель | Идентификатор | Назначение |
| --- | --- | --- |
| Gemini 3.1 Flash Lite | `google/gemini-3.1-flash-lite` | По умолчанию для чата и ряда бизнес-функций |
| GPT-5 Mini | `openai/gpt-5-mini` | Доступна для выбора |
| Claude Sonnet 4.6 | `anthropic/claude-sonnet-4-6` | Доступна для выбора |
| Gemini 2.5 Flash | `google/gemini-2.5-flash` | Парсеры источников; настраивается отдельно |

В справочнике определены `MODELS`, `DEFAULT_MODEL_KEY`, `DEFAULT_GATEWAY_ID`, `WEB_SEARCH_MODEL` и функции разрешения ключа модели в идентификатор Gateway.

## Где используется AI

| Функция | Модель и настройка | Основной код |
| --- | --- | --- |
| Глобальный AI-чат | Выбор из общего справочника | [`api/chat/route.ts`](../../src/app/api/chat/route.ts) |
| Ассистент аналитики | Модель по умолчанию из справочника | [`analytics/assistant/route.ts`](../../src/app/api/analytics/assistant/route.ts) |
| Генерация карточек по правилам | Выбранная модель через `modelKey` | [`cards-generation.ts`](../../src/server/cards-generation.ts) |
| Поиск сделок в источниках | Выбранная модель через `modelKey` | [`deals-discovery.ts`](../../src/server/deals-discovery.ts) |
| Разбор сообщения клиента в позиции заказа | Переданная модель или модель по умолчанию | [`order-requests.ts`](../../src/server/order-requests.ts) |
| Анализ сохранённой AI-переписки | Модель по умолчанию | [`save-chat-session.ts`](../../src/server/save-chat-session.ts) |
| Обогащение компаний из интернета | Два вызова: исследование, затем структурирование; модель по умолчанию | [`clients.ts`](../../src/server/clients.ts) |
| Веб-поиск для чата | Отдельный Gemini-вызов, `WEB_SEARCH_MODEL` | [`web-search.ts`](../../src/server/web-search.ts) |
| Разбор писем, чатов, Telegram, WhatsApp, Drive и файлов | Gemini 2.5 Flash | [`parser-config.ts`](../../src/lib/parser-config.ts), [`parsers/`](../../src/server/parsers/) |
| Определение принадлежности материала своей организации | Текстовая модель парсера | [`org-attribution.ts`](../../src/server/parsers/org-attribution.ts) |

Парсеры обрабатывают текст, PDF, изображения, аудио, видео и Office-документы. Они извлекают содержание в Markdown, резюме, упоминания людей, компаний и другие структурированные данные. Аудио и видео передаются модели для распознавания речи и определения говорящих. Из Office-документов текст предварительно извлекается серверным кодом.

## Конфигурация и адреса запросов

### Авторизация и окружение

Используется переменная окружения `AI_GATEWAY_API_KEY`. Она предусмотрена в [`deploy/k8s/app/env.example`](../../deploy/k8s/app/env.example).

В Kubernetes окружение приложения поступает из Secret `crm-env`: см. [`deployment.yaml`](../../deploy/k8s/app/deployment.yaml).

### Адрес Gateway

В установленной при проверке версии `@ai-sdk/gateway` (`3.0.88`) адрес по умолчанию в исполняемом коде SDK:

```text
https://ai-gateway.vercel.sh/v3/ai
```

Приложение передаёт строку вида `google/gemini-2.5-flash` в `generateText` или `streamText`; SDK маршрутизирует запрос через Gateway. Отдельного переопределения адреса в коде приложения не обнаружено. При обновлении SDK адрес по умолчанию следует проверить повторно.

Таким образом, приложение обращается к Vercel, который далее маршрутизирует запрос к провайдеру модели. Прямых LLM-интеграций с API OpenAI или Anthropic в проверенном коде не обнаружено. Конкретный upstream-адрес и маршрут внутри Gateway из этого репозитория не определяются.

### Где задаются параметры

| Место | Настройки |
| --- | --- |
| [`llm-models.ts`](../../src/lib/llm-models.ts) | Список моделей, значения по умолчанию, модель веб-поиска |
| [`parser-config.ts`](../../src/lib/parser-config.ts) | Модели парсеров, допустимые форматы, ограничения размера файлов |
| Файлы отдельных функций | Промпты, схемы ответа Zod, параметры генерации, ограничения количества шагов |
| Пользовательские правила карточек и сделок | Дополнительные инструкции, передаваемые в промпт |

Модели сейчас задаются в коде, а не единым набором переменных окружения.

## Особенности замены

### Веб-поиск привязан к Google

Используется `google.tools.googleSearch({})` из `@ai-sdk/google`:

- В [`web-search.ts`](../../src/server/web-search.ts) — веб-поиск чата.
- В [`clients.ts`](../../src/server/clients.ts) — исследование при обогащении компаний.

Даже если в чате выбран GPT или Claude, поиск в интернете выполняется отдельным вызовом Gemini. Для полного отказа от Google потребуется заменить оба места. Простая смена `WEB_SEARCH_MODEL` на модель другого провайдера не заменяет Google Search tool.

Веб-поиск возвращает результаты исследования, ссылки на источники и признак наличия подтверждения поиском (`grounded`). При замене нужно сохранить этот контракт или адаптировать его потребителей. Обогащение компаний дополнительно получает содержимое известного сайта компании обычными HTTP-запросами.

### Парсерам нужна мультимодальность

Замена Gemini на текстовую модель не обеспечит прямую обработку изображений, PDF, аудио и видео. Нужно либо подобрать модель с нужными форматами входа, либо разделить обработку:

```text
Файл → OCR / распознавание речи / извлечение текста → текстовая LLM
```

В [`parser-config.ts`](../../src/lib/parser-config.ts) для разных типов входа предусмотрены отдельные настройки моделей, поэтому их можно заменять поэтапно.

### Структурированные ответы, streaming и вызов инструментов

Большинство бизнес-функций использует `generateText` + `Output.object({ schema })`. Новый провайдер должен корректно возвращать данные по заданной схеме.

Чату дополнительно нужны потоковая выдача и вызов инструментов. Совместимость этих возможностей нужно проверить отдельно от обычной текстовой генерации.

### Инструменты CRM — собственный серверный код

`searchEverything`, `getSourceItemContent` и `queryAnalytics` выполняют поиск и запросы внутри приложения. Их обычно можно сохранить при замене модели. Найденные данные передаются модели как контекст.

Инструменты глобального чата описаны в [`api/chat/route.ts`](../../src/app/api/chat/route.ts), инструмент аналитики — в [`analytics-assistant.ts`](../../src/server/analytics-assistant.ts).

### Какие данные уходят модели

В зависимости от функции модель получает историю чата, найденные CRM-данные и материалы источников, тексты клиентских запросов, данные аналитики, информацию о компаниях либо содержимое загруженных файлов. При текущем маршруте эти данные проходят через Gateway и далее к провайдеру модели.

### UI-библиотеки — отдельный слой

`@ai-sdk/react`, `ai-elements`, Streamdown и json-render обеспечивают взаимодействие с чатом и отображение ответа. Это не отдельные провайдеры моделей. Наличие компонентов image/audio/transcription само по себе не означает подключения отдельного сервиса генерации.

В компоненте голосового ввода также предусмотрено использование браузерного `SpeechRecognition` / `webkitSpeechRecognition`: [`speech-input.tsx`](../../src/components/ai-elements/speech-input.tsx). Это отдельный механизм от серверного разбора аудиофайлов Gemini; конкретный сервис распознавания зависит от реализации браузера и в коде проекта не задан.

## Предлагаемый порядок замены

1. Ввести единый серверный слой выбора провайдера и модели и провести через него все LLM-вызовы.
2. Перенести обычные текстовые функции, проверяя структурированные ответы, streaming и вызов инструментов.
3. Отдельно заменить веб-поиск в чате и обогащении компаний.
4. Перенести мультимодальные парсеры с проверкой каждого типа файлов.
5. Обновить окружение, секреты и зависимости после устранения старых вызовов.

Одной смены API-ключа или записи в общем справочнике для полной замены недостаточно.
