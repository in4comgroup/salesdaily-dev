# Этап 2: проверка Yandex AI Studio

> **История (11 ноября 2026 года).** JSON-профили `config/ai/*.json`, `deploy/k8s/app/ai-config.json`, ConfigMap `crm-ai-config`, `AI_CONFIG_PATH` и команда `profile` удалены. Конфигурация хранится в БД и меняется в «Настройки → Модели → Маршруты ИИ»: [config-in-db-spec.md](config-in-db-spec.md). Ниже — описание на момент написания.

Реализован прямой адаптер Chat Completions. Текстовые сценарии и проверки маршрутов подключены к приложению; тесты протокола используют подменённый HTTP transport. Проверка реального каталога Yandex, качества и доступных квот выполняется владельцем окружения. Реальные ключи и данные CRM при разработке не использовались.

## Профили

| Файл | Поведение |
| --- | --- |
| `config/ai/blocked.json` | Все AI-задачи запрещены; ключи не требуются |
| ~~`config/ai/legacy.json`~~ | Удалён 11 ноября 2026 года вместе с адаптером Gateway (только Yandex) |
| `config/ai/yandex.json` | Прямой Yandex для текста; внешние возможности и неподдерживаемые файлы выключены |

`AI_CONFIG_PATH` обязателен при запуске приложения. При ошибочной конфигурации, отсутствии активных ключей или URI приложение не должно запускаться с запасным провайдером. В Next.js конфигурация проверяется через instrumentation для Node.js runtime; при сборке production-пакета проверка не требует боевых ключей. Процесс кеширует конфигурацию: после изменения файла или окружения нужен перезапуск.

## Локальные настройки на Mac

Установите зависимости по обновлённому lockfile:

```bash
corepack pnpm@10.34.6 install --frozen-lockfile
```

Внешний файл `~/.config/crm/local.env` из [инструкции запуска](../deploy/local-run.md) дополните:

```bash
AI_CONFIG_PATH='config/ai/yandex.json'
YANDEX_AI_API_KEY='СЕКРЕТНАЯ_ЧАСТЬ_API_КЛЮЧА'
YANDEX_AI_FOLDER_ID='ID_КАТАЛОГА'
YANDEX_AI_TEXT_MODEL_URI='gpt://ID_КАТАЛОГА/ИМЯ_И_ВЕРСИЯ_МОДЕЛИ'
```

Полный model URI возьмите из Model Gallery для вашего каталога. Например, в документации структурированного вывода используется `gpt://<folderId>/yandexgpt-5.1`, но доступность и возможности конкретной модели нужно проверить в вашем аккаунте. URI обязан относиться к `YANDEX_AI_FOLDER_ID`; произвольные адреса вместо URI не принимаются.

Нужны права сервисного аккаунта и scope ключа для выбранной модели; актуальные требования см. в [аутентификации](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication) и [примере structured output](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured).

Можно создать несколько моделей в JSON: у каждой свой внутренний ID, подпись и `upstreamModelIdEnv`, у задач — свои `defaultModel` и `allowedModels`. Секреты остаются в окружении. Профиль-пример использует один model URI для всех текстовых задач; это стартовая конфигурация, не подтверждение одинакового качества для всех задач.

## Проверки без сети

```bash
node tools/ai/run.mjs test
node tools/ai/run.mjs check --config config/ai/blocked.json
node tools/ai/run.mjs check --config config/ai/blocked.json --probe chat
```

Последняя команда должна завершиться с кодом 1 и сообщением об отключённой задаче, без отправки запроса. Тесты используют синтетические ключи и не требуют ключей Yandex.

Launcher компилирует только AI tooling через TypeScript во временную папку и удаляет её после запуска. Он не зависит от нативного esbuild. CLI читает переменные процесса; `.env.local` / `.env` автоматически **не загружаются**. Для приложения Next.js его штатная загрузка `.env*` сохраняется.

## Проверки с вашим каталогом

В своём обычном терминале вставьте целиком:

```bash
(
  set -a
  source ~/.config/crm/local.env || exit 1
  set +a
  node tools/ai/run.mjs check
)
```

Это проверяет конфигурацию и наличие активных настроек, не выполняя запрос. Для реальных запросов по очереди запускайте блок, заменяя последнюю команду на одну из следующих:

```bash
node tools/ai/run.mjs check --probe chat --mode text
node tools/ai/run.mjs check --probe orderRequest --mode structured
node tools/ai/run.mjs check --probe chat --mode tools
node tools/ai/run.mjs check --probe chat --mode stream
```

Каждая команда — отдельная платная проверка на синтетическом тексте. Tools-тест исполняет только локальную проверочную функцию, без чтения БД. Ожидается `Probe succeeded (...)`. Эти проверки не заменяют оценку качества реальных сценариев и региональных условий.

Адаптер использует `https://ai.api.cloud.yandex.net/v1/chat/completions`, `Authorization: Api-Key`, `OpenAI-Project` и `x-data-logging-enabled: false`. Редиректы запрещены; произвольный адрес и чужой каталог отвергаются. Настройка логирования не равна отключению всех видов хранения провайдером: см. [инструкцию](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging) и [политику хранения](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage). Responses / Conversations здесь не используются, трейсинг специально не включается.

В обычном режиме ошибки HTTP сообщаются без содержимого ответа провайдера, например `HTTP 401`. Проверьте ключ и права при 401/403, доступность URI и поддержку параметров при 400/404, квоты при 429, соединение / сервис при 5xx. Тело запроса и ответа можно включить отдельно через `--debug`, как описано ниже.

Если проверка не проходит, последняя строка показывает безопасную категорию: `http` с HTTP-статусом, `network` с известным кодом вроде `ENOTFOUND`, `timeout`, `response` (неожиданный формат ответа) или `unknown`. Пустой видимый ответ модели и незавершённый tool loop имеют отдельные сообщения. В обычном режиме произвольные названия/коды ошибок, тексты запросов/ответов, заголовки и ключи не выводятся. Первая строка подтверждает только наличие настроек, а не действительность ключа. Для первичной диагностики можно передать последнюю строку; полное окружение или ключи не нужны. Категория `unknown` сама по себе не указывает на неверный ключ — выполните debug-проверку.

### Тело запроса и ответа для диагностики

Из корня проекта в обычном терминале Mac вставьте весь блок. Он загружает настройки из внешнего файла и явно включает вывод тела для синтетического Yandex probe:

```bash
(
  set -a
  source ~/.config/crm/local.env || exit 1
  set +a
  node tools/ai/run.mjs check --probe chat --mode text --debug
)
```

Если окружение уже загружено в текущем терминале, достаточно последней команды внутри скобок. Это платный синтетический запрос без чтения CRM. Будут выведены `AI DEBUG request ... body` и `AI DEBUG response HTTP ...` с телами JSON. Заголовки не выводятся; API-ключ, auth-поля и известные секретные поля маскируются, включая ключ, отражённый провайдером в ответе. Вывод ограничен 64 KiB на тело. Model URI с ID каталога остаётся видимым.

Ожидаемая последовательность:

```text
AI DEBUG enabled for synthetic Yandex probes; headers and API key are redacted.
...
Synthetic text probe: chat → yandex / yandex-text
AI DEBUG request 1 body (authorization omitted):
{ ... }
AI DEBUG response HTTP <статус>:
{ ... }
Probe succeeded (text).
```

При ошибке вместо последней строки появится `AI check failed (...)` или другое диагностическое сообщение. Для разбора передайте блоки `AI DEBUG request`, `AI DEBUG response` (если он появился) и последнюю строку ошибки. ID каталога в URI можно дополнительно замаскировать. Не передавайте файл окружения или вывод `env` / `printenv`.

Debug применяется только к явному CLI probe, не включает логирование запросов приложения и не меняет `x-data-logging-enabled: false`. Для streaming тело SSE не выводится, чтобы не потреблять поток; используйте `--mode text` для изучения ответа. Если показан запрос, но нет строки ответа, HTTP-ответ ещё не был получен либо произошла ошибка его чтения. Отсутствие строки запроса указывает на ошибку до вызова transport.

## Проверка интерфейса

Запустите приложение с тем же внешним файлом окружения и обновите открытые вкладки после смены политики:

```bash
(
  set -a
  source ~/.config/crm/local.env || exit 1
  set +a
  corepack pnpm@10.34.6 dev
)
```

- `/api/ai/config` отдаёт только разрешённые внутренние ID, подписи, возможности и публичные флаги, без секретов / адресов / model URI.
- В чате, диалогах карточек и сделок доступны модели из этого каталога. Старый сохранённый / подставленный ID не позволяет обойти серверную политику.
- Кнопки Magic используют default своей задачи на сервере, без захардкоженного Gemini.
- Проверьте чат с CRM-инструментами, аналитику, карточки, сделки, разбор заказа, сохранение переписки, текстовые источники и DOCX/PPTX.
- Для непроверенного окружения используйте синтетические либо отдельно разрешённые данные. Сначала подтвердите регион и условия обработки.

В Yandex-профиле Google Search, веб-обогащение компаний, прямое чтение сайтов, browser SpeechRecognition, вложения в текстовом чате и мультимодальные парсеры отключены. Чат не получает web tool и промпт не обещает веб-поиск. Вложения не отправляются Yandex через прямой подставленный запрос. Попытка парсинга неподдерживаемого файла завершается ошибкой политики, без вызова Gemini; исходная запись / файл не удаляются.

Существующая логика «заказ из запроса» при ошибке AI сохраняет возможность ручной сборки и показывает `parseError`. Атрибуция при недоступном LLM оставляет детерминированный результат. Отключение задачи не всегда означает отключение всего содержащего её бизнес-процесса.

Список прогресса и причин отключения: [roadmap](roadmap.md). Конфигурация Kubernetes: [ai-configuration.md](../deploy/ai-configuration.md).

## Границы проверки

Протокольные тесты не подтверждают фактическую доступность модели, квоты, качество распознавания или региональное размещение всех сервисов CRM. Существующие почта, источники, S3, OAuth и другие внешние интеграции остаются отдельными маршрутами. Региональный допуск всего приложения и проверка исходящего трафика относятся к этапу 4.

32 теста прошли, включая запрет файлов в текстовом чате и отклонение удалённых медиа до скачивания SDK. ESLint всех изменённых TS/TSX-файлов и AI tooling прошёл. Проверка TypeScript затронутого графа зависимостей прошла с увеличенным лимитом памяти. YAML манифестов, ссылка на ConfigMap, путь mount и blocked-профиль по умолчанию проверены. CLI blocked/Yandex-профилей проверяется без сети с синтетическими настройками. Production build, браузерная проверка приложения и реальные Yandex probes не выполнялись.
